## The "AI" logic (matchDepartment.js) — how symptom → doctor actually works
This is a **lookup table, not a real model call**. It's honest to describe it this way to judges too: it's a rules-based NLP-flavored router, which is a legitimate and common hackathon pattern for "AI-assisted" triage demos.

```js
// keywordMap.js
export const keywordMap = {
  dermatology:   ["skin", "rash", "itch", "acne"],
  cardiology:    ["chest pain", "heart", "breath"],
  orthopedics:   ["leg", "knee", "back pain", "bone", "joint"],
  pediatrics:    ["child", "baby", "fever in child"],
  gynecology:    ["women", "pregnancy", "period"],
  dentistry:     ["tooth", "teeth", "gum"],
  ophthalmology: ["eye", "vision", "blurry"],
};

// matchDepartment.js
export function matchDepartment(inputText) {
  const text = inputText.toLowerCase();
  for (const [dept, keywords] of Object.entries(keywordMap)) {
    if (keywords.some(k => text.includes(k))) return dept;
  }
  return null; // triggers "please describe your symptom differently" prompt
}
```
Doctor picking: filter `doctors.json` by matched department → if 1+ doctors found, generate 5 next-day time slots (e.g. 9:00, 10:30, 12:00, 15:00, 17:00) → if the "randomly" chosen doctor is flagged `available: false` in the JSON, show the unavailable state with 4 centres from `centres.json`.

## The Emergency path (no login, works with no data)
Per your spec, Emergency must work **without login and without network**. Three one-tap actions, all zero-backend:

1. **Call Ambulance** — `<a href="tel:108">📞 Call Emergency</a>` (or your dummy number). Opens dialer pre-filled; user confirms with one more tap. No network needed — this is a standard cellular voice call, not data.
2. **Call Family/Husband** — same pattern, `tel:` link using a number stored in `AppContext` (set once during onboarding, or hardcoded for the demo).
3. **Share Live Location** — no internet required, works via GPS hardware directly:
   ```js
   // utils/location.js
   import { Geolocation } from '@capacitor/geolocation';

   export async function shareLocationViaSms(phoneNumber) {
     const pos = await Geolocation.getCurrentPosition(); // reads GPS chip, offline-capable
     const { latitude, longitude } = pos.coords;
     const mapsLink = `https://maps.google.com/?q=${latitude},${longitude}`;
     const body = encodeURIComponent(`Emergency! My location: ${mapsLink}`);
     window.location.href = `sms:${phoneNumber}?body=${body}`; // opens SMS app pre-filled
   }
   ```
   User taps Send once in their SMS app to actually send it — this is a platform restriction (both Android and iOS require a manual confirmation for user-initiated SMS from a web/Capacitor context; true silent background sending needs a native plugin, which is out of scope for this build).

All three actions live on `Emergency.jsx`, reachable directly from `Hero.jsx` with **no auth check** in the route — this is the literal meaning of "works with no login."

## State management
One `AppContext` holding: `{ user, familyMembers, selectedSymptomText, matchedDepartment, selectedSlot }`. No global store library — passed via React Context, read with `useContext` in the 3-4 screens that need it (Voice Booking → Results → Confirmation).
